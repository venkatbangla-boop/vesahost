### The AQL 11.78 MB root cause — exact bytes

- **294 embedded Base64 data URLs = 10,715,539 bytes (90.94% of raw HTML source)**.
- These are **291 PNGs (10,376,506 bytes) and 3 JPEGs (339,033 bytes)**.
- 292 unique media payloads out of 294 occurrences; the two repeat occurrences represent only ~226,022 bytes of potential same-file deduplication before compression. Mass deduplication alone is **not** the answer.
- The largest single HTML line has **9,052,221 bytes**. A giant inline script includes many asset literals and app classes. Script and style regex sizes can overlap when markup-looking text appears within a script literal; do not add raw script/style sizes to the Base64 total.
- AQL source declares 99 classes. Actual domain-specific examples include \`SamplingEngine\`, \`CartonSelectionEngine\`, \`MeasurementEngine\`, \`FabricInspectionEngine\`, \`PackingEngine\`, \`ProductionInspectionEngine\`, \`LoadingInspectionEngine\`, \`PreFinalReadinessEngine\`, \`ReinspectionService\`, \`StageDecision\`, \`ResultEngine\`, \`ReportComposer\`, \`OfflinePdfPages\`, \`ProjectTransfer\`, \`AutosaveService\` and \`BackupVault\`. Class count includes UI/compatibility wrappers, not 99 unique commercial calculations.
- AQL architecture's strengths are domain/state coverage, staged inspections, validations, evidence management, local recovery, synthetic workflow reports and source-checked sampling. It is **not automatically perfect**: monolithic HTML, embedded media, multi-level navigation cost and conditional provider adapters deserve separate review.

**Recommended AQL performance work:** profile cold startup/load and CPU decode on an actual mobile-class Chromium throttle and real device; audit PNG image use, decode and memory; only then split or optimize images with exact offline cache and print/PDF parity. Preserve all AQL Ac/Re, carton provenance, inspection outcomes, photo evidence, 15-report blueprint and existing saved-copy compatibility. ## 2. AQL strengths that should be applied correctly elsewhere

1. **Full task lifecycle:** New/open → validated entry → task-specific stages → evidence/exception → reviewed decision → saved history → report → reopen. Not eight decorative tiles leading to one form.
2. **Data completeness:** typed source-backed records, explicit blanks, quantities/units, warnings and traceability; never invent buyer, bank, factory, shipment or approval values.
3. **Calculation ownership:** each app has its own approved domain engine. Never copy AQL sampling Ac/Re into packing or recreate TNA CPM in Production.
4. **Differentiated navigation:** one shared branded shell with real app-specific content, dense desktop work area and progressive mobile focus; proper 44px actions.
5. **Reports:** layered summary + detailed register + exceptions + history + source references. Current portfolio apps already generate actual XLSX in many cases and browser printable reports; deepen formats where a report-model/user task requires it, not by inventing 15 arbitrary PDFs per app.
6. **Recovery/compatibility:** versioned local saved copies, safe invalid-input rejection, old-copy migration, browser-local backup/restore and tested offline readiness.
7. **Prove the whole path:** every enabled button, submit, form, print/export and reopening with real Chromium fixtures, after engine parity assertions, plus separate human signoff.
